# GB10 G256 CUTLASS 优化实验

已实现 BF16 共享内存写回、BF16 成对直接写回，以及异步 scale staging。保留 CUTLASS 的 GemmUniversal / GemmUniversalAdapter 和原版配置。

18 个模型投影形状全部完成，M 是实际 GEMM 行数；不对专家应用 M=T/8 换算。LM head 测所有 M 行。纯 INT8 G256 GEMM，FP32 scales 和跨组累加，BF16 输出。时间包含组缩放与输出转换，不包含量化。

这次在同一轮同时加载原版和新版 CUTLASS 动态库，并重测 CuTe、Triton；不是与上一次报告的历史数字直接相减。每个实现分别调参，再用新输入做五轮独立复测。使用 CUDA Graph、预分配输出、重复输入且不清缓存。编译、调参和主机调用不计时。

整体选择的中位数：16 个形状改善，1 个基本持平，1 个约 0.96% 回退且轮次范围重叠。M2048 两个 LM head 的延迟分别下降约 9.00% 和 7.21%。新版 CUTLASS 仍比同轮 CuTe 慢 0.44%–3.84%；很小的差距不能视为稳定显著领先。

## 优化配置与消融

- 0–7：原版 FP32 共享内存交换，寄存器 scale 预取。
- 8–15：先转 BF16 再通过共享内存交换，寄存器 scale 预取。
- 16–23：异步共享内存 scale staging，BF16 成对直接写回。
- 24–31：寄存器 scale 预取，BF16 成对直接写回。

每组八个配置拥有相同的 tile/stage 排列。全部 32 个配置没有寄存器 spill。普通投影主要选择 BF16 共享内存交换；4 个 LM head 选择配置 23。直接写回在普通投影上可能更慢，异步 scale 相对寄存器 scale 的收益也不一致，因此按形状选配置。

原始报告包含各 family 的独立选优结果与五轮范围。同 tile 消融应比较同一 case 的 tuning 中相同 config_id modulo 8 的配置；family 最优值可能来自不同 tile，不能混为同 tile 消融。overall winner 和所属 family winner 是同一个 kernel 的两组独立重测，数字有小差异属于测量波动。

## 验证和集成

- 667 项测试通过，覆盖全部 32 配置、短 K、奇数组循环、跨 CTA scales、INT8 极值、signed/zero scales、FMA cancellation、CUDA streams 和 graph replay。
- memcheck：0 errors；racecheck：0 hazards / 0 errors / 0 warnings。
- 1188 个候选、144 个最终测量记录通过统计和来源审核，所有记录的 32×32 抽样参考最大误差为 0。每个输出还检查 finite；选中的 graph 检查 fresh-input 与 zero/restore。抽样检查不等于每个元素都与 CPU 参考逐一比较。
- 18 条配置已写入独立的 sm121_g256_cutlass.json，仅供 backend="cutlass" 自动选择。auto / cuda / triton 原策略保持不变。
- 本地工作，未提交、未推送。
