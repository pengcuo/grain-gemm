# GB10：M=4096、G256，CuTe 与 CUTLASS 对比

沿用上一轮固定配置，将 M 改为 4096。没有重新调参，结果不代表每个后端在这些新形状上的最优配置。前一轮三个展示形状中，有两行的 N/K 相同；统一 M 后合并为一组，另补测原报告中的 128×64 tile 与 LM head。

NVIDIA GB10；INT8 A/B、FP32 scales/累加、BF16 输出。只测预量化后的 GEMM，包括分组缩放和输出转换，不含量化、编译、输入生成或 host 调度。输出缓冲区预分配，重复输入、warm cache。TOPS = `2*M*N*K / (延迟秒 * 10^12)`，整数乘加按 2 个 operation 计，未另计 scale/转换的运算量。

K 下界实验版仅增加设备端 `if (K < 256) return;`，仍使用原 CUTLASS Adapter/collective/epilogue。去尾部同步实验版是另一个独立改动，未与 K 下界改动合并。

按同轮次配对统计，K 下界实验版在两个 cfg15 投影上的延迟仍比 CuTe 低 1.55% 和 1.13%；cfg11 投影仍慢 1.08%，LM head 仍慢 3.03%。因此上一轮 cfg15 上的优化效果在这两个 M=4096 形状上延续，但优势没有推广到所有配置。LM head 单独去尾部同步的实验版仍比 CuTe 慢 2.55%。

固定配置：N=1024/K=1536 使用 CuTe 3 / CUTLASS 11（128×64 tile）；N=1536/K=1024 和 N=2048/K=1536 使用 CuTe 7 / CUTLASS 15（128×128 tile）；LM head 使用 CuTe 15 / CUTLASS 23（128×128 tile、async scales、直接写回）。均为 3 stages。不同后端配置编号属于各自的配置表。

每个形状在同一组输入、scales、输出缓冲区上交错执行 5 条路径：CuTe、正式 CUTLASS、同机器码对照、K 下界改动、去尾部同步改动。60 轮，每轮每路径 3 次 CUDA event 计时；路径轮换并反转顺序，每条路径在每个执行位置恰好出现 12 次。每个形状各路径使用相同 CUDA Graph 节点数。表格延迟为轮次中位数的中位数。未锁时钟，原始 JSON 保留温度/时钟记录。

每条路径在计时前及 graph replay 后进行 32×32 输出采样参考检查，以及全输出 finite 检查。检查的参考逐 K-group 执行 INT32 点积、FP32 scale 累加及 BF16 转换；采样不等于大矩阵全量逐元素验证。原始 JSON 记录采样误差。此前这些二进制通过的完整小形状参考验证和 sanitizer 结果见[上一轮报告](/home/pengcuo/spark/experiments/grain-cutlass-residual-gap/report.md)。
