# M=256 CuTe 性能回退：根因调查（历史测量）

> 本报告记录 2026-09-23 修复前的实验状态。下文的“默认”指测量时的配置；三个精确 M/N/K 形状现已接入自动分配。原始 JSON/CSV 保持字节不变，性能数据没有重新测量或改写。当前 API 默认输出为 BF16；本实验当时已显式指定 BF16。

2026-09-23，NVIDIA GB10 / SM121 / 48 SM；G256，预量化 INT8 输入、FP32 scales、BF16 输出。

## 结论

问题首先出在未测量矩形形状的 **CuTe 默认配置选择**：`backend="cuda"` 仅根据 M/N 是否为 128 的倍数选 cfg7（128×128、8 warps、3 stages），没有根据输出网格规模选择 tile。小矩阵因此只有 16/24 个 CTA，无法覆盖 48 个 SM。

现有 cfg3/cfg5 的小 tile 能把 CTA 分散到更多 SM。保持同一个 kernel 不变的 M/N 扫描，又在 48 个可驻留 CTA 的边界复现了明显的延迟跳变，支持 **网格粒度与分批调度** 是主要结构性原因。不能把所有 M256 都改成小 tile：N2048 时小 tile 超过一批，现有大 tile 更快。

这里的“CuTe 默认”是显式 `backend="cuda"`。测量时这些矩形形状没有命中方阵测量表，`backend="auto"` 当时选 Triton；现已按三个精确形状接入 CuTe。

## 根因的代码位置

- [gemm.py:113](https://github.com/pengcuo/grain-gemm/blob/63a72f1d6487c5305d179d2d77ad43e1f4602c91/src/grain_gemm/gemm.py#L113)：矩形 native fallback 只判断 M/N 对 128 的整除性，选 cfg7 或 cfg0。
- [int8_g256_cute.cu:413](../../../src/grain_gemm/kernels/csrc/sm12x/int8_g256_cute.cu#L413)：二维网格为 `(M/BM, N/BN)`。
- [int8_g256_cute.cu:426](../../../src/grain_gemm/kernels/csrc/sm12x/int8_g256_cute.cu#L426)：所有本次 K1024/K1536 实验均走同一 2D 遍历分支。
- [int8_g256_cute.cu:437](../../../src/grain_gemm/kernels/csrc/sm12x/int8_g256_cute.cu#L437)：cfg3=128×64/W4/P3，cfg5=64×128/W4/P3，cfg7=128×128/W8/P3。三者相同的 scale 预取与 128-bit 写回策略。

cfg7 与 cfg3/5 都只能驻留 1 CTA/SM。小 tile 的 CTA 翻倍，但每 CTA 从 8 warp 降为 4 warp；总线程/warp 数没有翻倍，每个活跃 SM 的 warp occupancy 也没有提高。改善的是 **工作在更多 SM 之间的分配粒度**。

## 保持同一 kernel 的边界实验

固定 M=256、K=1536，只变 N。三列分别为 cfg3、cfg5、cfg7；小 tile 首次跨过 48 CTA 的点为 N1664，大 tile 为 N3200。

| M | N | K | cfg3/5 CTA | cfg7 CTA | cfg3 μs | cfg5 μs | cfg7 μs |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 256 | 1024 | 1536 | 32 | 16 | 8.736 | 8.810 | 15.040 |
| 256 | 1408 | 1536 | 44 | 22 | 10.032 | 9.943 | 15.088 |
| 256 | 1536 | 1536 | 48 | 24 | 10.135 | 10.157 | 15.131 |
| 256 | 1664 | 1536 | 52 | 26 | 17.642 | 17.816 | 15.365 |
| 256 | 2048 | 1536 | 64 | 32 | 18.260 | 18.040 | 15.405 |
| 256 | 2944 | 1536 | 92 | 46 | 19.147 | 19.280 | 16.460 |
| 256 | 3072 | 1536 | 96 | 48 | 19.720 | 19.912 | 16.504 |
| 256 | 3200 | 1536 | 100 | 50 | 26.848 | 27.001 | 31.213 |

N1536→1664：工作量只增加 8.3%，cfg3 从 10.135→17.642 μs（+74.1%），而尚未跨边界的 cfg7 为 15.131→15.365 μs。N3072→3200：工作量只增加 4.2%，cfg7 从 16.504→31.213 μs（+89.1%）；同时小 tile 也从 96→100 CTA，跨过第二批容量，所以三种配置均变慢。每次比较中 kernel 二进制、tile、K、流水线深度均不变。调度并非严格同步的“波次”，这里描述的是驻留容量与尾部任务的效应。

再固定 N1024、K1536，只变 M，复现同样的边界；这也说明 M=256 本身没有特殊的慢路径。

等面积的两个形状 `(256,3072,1536)` 与 `(768,1024,1536)` 的 cfg7 都为 48 CTA，分别耗时 16.504/16.517 μs；cfg3 都为 96 CTA，分别为 19.720/19.664 μs。不同长宽与 stride 仍得到接近的时间，进一步削弱单一 N 访问布局问题的解释。

## 已排除与尚未量化的因素

- **寄存器 spill：**全部 34 个已编译变体（17 config × 2 遍历）均 STACK0/LOCAL0，无 LDL/STL。cfg7 寄存器使用量大，但没有溢出到 local memory。
- **没有使用 Tensor Core：**SASS 使用 `IMMA.16832.S8.S8`；FP32 转换、乘法和 FFMA 属于正常的 group scaling/accumulation。
- **仅流水线 P3 太深：**cfg7→cfg6 只把阶段降为 2，网格和寄存器数量不变，两个慢形状分别为 15.040→15.132 μs、11.272→11.388 μs，未解决回退。
- **Python 调度/临时分配：**计时只包含预分配输出上的 CUDA graph 回放，排除了 Python 调用、编译、量化与分配。
- **M256 特殊分支：**native 内核与 dispatch 没有 M256 专属分支。M/N 扫描在相同 kernel 中复现网格容量边界。
- **剩余限制：**改变 tile 同时改变 A/B 重用、每 CTA 资源及生成指令调度，因此不能把两配置间的全部时间差唯一分解为 SM 覆盖不足。没有独立定量归因每个 stall 类型。
- **硬件计数器：**Nsight Compute 被现有系统权限拒绝（`ERR_NVGPUCTRPERM`）；未修改驱动设置。本结论基于源码、二进制、CUDA 驻留查询和定时对照，不宣称测得 achieved occupancy 或 Tensor Core utilization。

## 建议修复范围

为测过的矩形形状补充 dispatch 选择，并考虑 CTA 数、每 SM 驻留上限及尾部不满：`(256,1024,1536)` 用 cfg3，`(256,1536,1024)` 用 cfg5，`(256,2048,1536)` 保留 cfg7。这些是当前 GB10/G256/BF16 条件下的候选，不推广成所有 M256、所有 K、所有设备通用规则。

本次诊断运行未修改 kernel 或 dispatch；之后已集成上述三个精确形状的 dispatch 选择。

## 方法与完整对照数据

14 个实验 case，69 个 shape/config 组合。所有配置对同一形状使用相同输入、scales 与预分配输出；跨 M/N 扫描使用固定随机种子的最大输入矩阵前缀。K1024/K1536、G256，A 行主序，B 的底层存储为连续 [N,K]。每个 case 独立进程串行运行。

每个配置捕获 256 次 GEMM 的图，预热后做 5 轮，每轮 9 次图回放；按每次图耗时/256 换算，取各轮中位数的中位数。每轮轮换配置顺序，不清缓存。JSON 保存全部 45 个回放时间及前后温度/频率；GPU 未锁频，运行于 P0。

每个配置使用 CPU INT32 group reduction 与 FP32 舍入参考检查最多 32×32 个输出样本，并检查全输出 finite；本次 69 个组合抽样 max_abs_error 均为 0。另外将 A 清零后回放，检查全输出为零，再恢复输入并复核样本。这不是全矩阵参考校验，也不是端到端模型精度测试。

各表为本次固定输入的比较，不与旧运行延迟交叉计算加速比。CuTe 默认配置是 cfg7；Triton 默认为 64×128/W8/P3，两个显式 Triton 候选为 64×128/W4/P3、128×64/W4/P3。
