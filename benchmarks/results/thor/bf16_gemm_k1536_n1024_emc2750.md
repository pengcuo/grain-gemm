# Thor default PyTorch BF16 GEMM: K1536, N1024

Measured 2026-10-21 19:51 CST. GPU frequency was reduced to **1.2 GHz (actual 1197 MHz)** and EMC fixed at **2750 MHz**. All minimum, maximum and current readings matched these locks before and after timed samples.

Default `torch.mm(a, weight.T, out=out)` is measured, with BF16 A `[M,1536]`, contiguous BF16 Linear weight `[1024,1536]`, and BF16 output `[M,1024]`. No backend preference or precision flags are changed. Output is preallocated. Input generation, graph capture, correctness checks, cache flush and host dispatch are excluded.

## Results

| M | Cold µs | Cold TFLOPS | Warm µs | Warm TFLOPS |
| ---: | ---: | ---: | ---: | ---: |
| 1024 | 113.024 | 28.50 | 28.544 | 112.85 |
| 2048 | 161.024 | 40.01 | 55.328 | 116.44 |
| 4096 | 218.720 | 58.91 | 92.224 | 139.71 |
| 8192 | 331.264 | 77.79 | 263.680 | 97.73 |

Throughput is `2*M*N*K / seconds / 1e12`, with one FMA counted as two operations. Cold samples clear a 256 MB buffer outside the timed events; warm samples reuse the same tensors with no flush. The peak among these four measured shapes is **139.71 TFLOPS at M4096**.

The [preceding CuTe-inclusive INT8 run](gemm_k1536_n1024_cute_emc2750.md) used the same shapes, layouts, locked frequencies and one-GEMM-per-replay timing. Those INT8 and these BF16 values were measured in separate runs with different synthetic inputs and confirmation sample counts; they are not paired, interleaved timing samples.

## Method and validation

Each replay contains one GEMM. Each cache mode has five rounds of five samples; latency is the median of round medians. There is no long sustained warmup. Default PyTorch settings were recorded as follows:

- PyTorch: `2.11.0a0+a6c236b9fd.nv26.03.46836102`; CUDA runtime: `13.2`.
- BLAS preference: `_BlasBackend.Cublas` (this preference does not identify the actual selected library algorithm).
- `allow_bf16_reduced_precision_reduction`: `True`.
- Float32 matmul precision: `high` (recorded for context; operands here are BF16).

For each shape, 27 sampled outputs across three rows and nine columns were compared with an independent CPU FP64 reference using the original BF16 operands (`rtol=1/128`, `atol=0.05`). Checks run before graph capture and again after timing; every output element is finite. This is sampled numerical validation, not a full-output numerical comparison.

| M | Maximum sampled absolute error vs CPU FP64 |
| ---: | ---: |
| 1024 | 0.245509 |
| 2048 | 0.210607 |
| 4096 | 0.200767 |
| 8192 | 0.170283 |

Benchmark/guard hashes were stable throughout the measurement. Maximum GPU temperature was 54.468 °C. The read-only guard pauses at 62 °C until 54 °C and aborts at 70 °C.
